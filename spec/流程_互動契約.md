# 流程_互動契約(輸入空間表)

本檔為圖台互動之行為契約:由**系統輸入空間**(元素 × 事件 × 狀態,自源碼 grep 全範圍取得)笛卡兒積推導,每格填「應然」;以測試鎖定.`流程_圖台互動.md` 之 E2E bullet 為本表之端對端抽樣.

## 1. 領域常規對標(動手前)

| 行為 | React Flow | draw.io | 本系統 |
|---|---|---|---|
| 連接點 | Handle 由節點宣告;`ConnectionMode.Strict` 分 source/target,`Loose` 則不分 | 固定連接點依形狀而異(矩形預設含四邊中點與四角)+ 浮動連接點 | **四邊中點各一,無出入之分**(近 React Flow Loose / draw.io 固定點子集) |
| 邊之方位 | 由 handle 決定 | 邊記 exit/entry 相對點 | **邊記 `fromPosition`/`toPosition`(top/right/bottom/left)** |
| 射出方向 | handle position(4 向) | 由 orthogonal 路由決定 | **外接矩形該邊之法向量(4 向)**,與 bezier 控制點/step 出入方向一致;三角形斜邊上之連接點亦水平/垂直射出 |
| 自哪個把手可出發建線 | source 與 target 皆可 | 任一連接點 | **任一把手** |
| 建線方向 | 自 source 出發 = from | 出發端 = source | **出發端 = from,落點端 = to** |
| 自我連線 | 由 validator 決定 | 允許 | **禁止**(self) |
| 重複邊 | 由 handle 對決定 | 允許 | **同向同節點對即重複(方位不參與)**——邊是 A→B 關係,方位是呈現屬性,可經表單改 |
| 箭頭 | markerStart/markerEnd(type/color/width/height,`markerUnits=strokeWidth` 隨線寬) | 起/終各自樣式、`startSize/endSize`(隨線寬放大)、填充 | **兩端各 type/size/faceColor(填色)/edgeColor(框色)**;鍵為 `markerFrom*`/`markerTo*`——**與 `conn.from`/`to`、`fromPosition`/`toPosition` 同一套 from/to 語彙**(SVG 之 `marker-start`/`marker-end` 僅為渲染屬性名,不外露為資料鍵);框色未給時跟隨線色(既有行為),外框寬=線寬;size 為**圖面 px**(隨 zoom 同比縮放、不隨線寬;刻意與二者不同——業主要求大小獨立可設) |
| 建線中不可連落點 | invalid class | — | invalid ring + not-allowed |
| fit 之 padding 單位 | 螢幕層(`'25px'`/`'10%'`/`{top,right,bottom,left,x,y}`,v12.5+) | — | **CSS 像素**(數值或 `{top,right,bottom,left}`);另對標 Leaflet `fitBounds` padding 與 OpenLayers `View.fit` `[top,right,bottom,left]`,三家皆螢幕層 |
| fit 是否為控制項讓位 | 否(`<Controls/>` 亦為 overlay,需自行加 padding) | — | **否(同三家)**:留白一律由 `fitViewPadding` 決定,0 = 貼邊;預設 50 > 預設選單右緣 40px 故預設不遮;Leaflet 官方文件明載 padding「usually left for controls」 |
| 設定面板之屬性組織 | 無內建設定面板 | Format panel 先分 Style / Text / Arrange 三 tab,tab 內再分段(連線另有 Waypoints、Line start / Line end 等獨立段) | **單層可摺疊群組**(節點 4 群 / 連線 5 群,各群獨立顯隱)。**借用的是「概念分離」而非資訊架構**:draw.io 官方文件只支持它把樣式/文字/排列與連線的路徑、兩端箭頭分開處理,未將各段定義為可摺疊群;Figma 官方文件支持 Typography 與 Fill/Stroke 分離,但未承諾固定的段落順序或每段皆可摺疊。群的數量、成員與順序為本系統依欄位語義與使用頻率之在地決策,非外部產品已驗證之規則 |
| 摺疊指示符號 | — | — | **三角形朝右 = 收合、朝下 = 展開**(符號表示「目前狀態」,非「按下去會怎樣」);同 macOS / Finder / Xcode 之 disclosure triangle 語義 |
| 一次一手勢 | 是 | 是 | **activeGesture 單值** |
| 手勢開始關閉浮層 | 是 | 是 | **closeAllPopups()** |
| 拖曳中他元素 hover | 不反應 | 不反應 | **vue-flow--gesturing 抑制** |
| affordance 之點擊代表宿主 | 否 | 否 | **否**(節點/邊一致) |
| 主鍵限制 | 是 | 是 | 是(把手/四角/轉折點/畫布/節點皆 `button===0`) |

## 2. 軸與成員(自源碼取得)

- **可命中元素**(`closest('.vue-flow__*')` 全集 + overlay):`popup`(Teleport 至 body,不在 flow DOM 內)/`panel`(工具列)/`node-gear`(含 anchor)/`edge-gear`(含 anchor)/`resize`(四角)/`handle`(top|right|bottom|left)/`waypoint`/`edge`(線本體+label 區)/`node`(本體,含 dragHandle/互動元素/nodrag 區)/`canvas`.
- **輸入事件**:mousedown / mousemove / mouseup / click / dblclick / contextmenu / mouseenter-leave(hover)/ wheel / keydown.
- **滑鼠鍵**:主鍵 / 非主鍵.
- **activeGesture**(單值):`null | pan | drag | resize | connect | waypoint | boxselect`.
- **overlay**(可疊加):`popup-open`(至多一個)/`multiselect`(複選鍵生效).
- **能力旗標**:`locked` / `elementsSelectable` / `nodesConnectable` / `nodesDraggable` / `nodesResizable` / `settingsEnabled`.
- **終止路徑**:mouseup / window blur / buttons 復原(視窗外放開)/ 元件 destroy / `locked` 切換.
- **形狀**:rectangle / diamond / ellipse / triangle-up / triangle-right / triangle-down / triangle-left(值域單一來源 `nodeStyle.SHAPES`; 設定表單之顯示文字由值轉寫 kebab → Title Case, 不另備對照表).
- **邊**:top / right / bottom / left.

## 3. 基線表(activeGesture=null,無 overlay,能力全開)

| hit | mousedown(主鍵) | click | dblclick | contextmenu | hover | 非主鍵 mousedown |
|---|---|---|---|---|---|---|
| popup | 交給 popup(不進 flow) | — | — | — | — | — |
| panel | 無手勢;不關 popup 之外的副作用 | 工具列動作 | **不發 canvas-dblclick** | **不發 pane-context-menu** | 工具列自身 | 無 |
| node-gear | 無手勢(不拖不平移);冒泡至 window 關他 popup | 開設定 + activate(sole) | **不發 node-double-click** | **不發 node-context-menu** | 齒輪 hover;宿主節點同時 hovered | 無 |
| (設定入口方式) | `opt.nodesSettingsTrigger` / `opt.connsSettingsTrigger` ∈ `hover \| click \| dblclick`(預設 `dblclick`):hover=移入顯示齒輪、點齒輪開設定;click/dblclick=該動作於本體直接開設定 popup(不顯示齒輪;click 模式資訊 popup 讓位);affordance 上之動作不開;同閘門(複選/手勢/locked 拒開) | | | | | |
| edge-gear | 同上 | 開設定 + activate | 不發 conn-double-click | 不發 conn-context-menu | 齒輪 hover(class 驅動);邊同時 hovered | 無 |
| resize | **resize 手勢** + activate + **closeAllPopups** | 無 | **不發** | **不發** | 四角 hover | **無**(button 守衛) |
| handle(四邊任一) | **connect 手勢** + closeAllPopups | 無(`.stop`) | **不發** | **不發** | 放大變藍(四把手皆可出發,承諾真實) | 無 |
| waypoint | **waypoint 手勢** + closeAllPopups | 無 | 不發 | 不發 | 轉折點 hover | **無** |
| edge(線本體 + label 文字;label 兩側空白不可點) | **無手勢,不平移**;label mousedown preventDefault(不選字不原生拖曳) | 選取 + info popup(hasInfoPopup 時;dblclick 模式延後 250ms,雙擊即取消)+ conn-click | conn-double-click | conn-context-menu | 線加深 + 齒輪出現 | 無 |

規則:**affordance(gear/resize/handle/waypoint/panel)永不代表其宿主元素或畫布發 click 類事件**;每次 mousedown 至多啟動一個手勢;四個把手行為完全相同,唯一差異是 `data-handle-position`;根元素 `dragstart.prevent`——圖台內任何原生拖曳(選取文字之文字圖層/圖片)一律取消,拖曳語義只有節點/轉折點/建線/平移.

## 4. 建線(connect)細則

- 出發:主鍵 + connectable + nodesConnectable + 未鎖定 + 非複選 + activeGesture=null.`connect-start = { nodeId, handlePosition }`.
- 候選:`{ from: 出發節點, to: 落點節點, fromPosition: 出發邊, toPosition: 落點邊 }`;宿主 validator / `connect` 事件收同形狀.寫入圖之新邊另帶 `markerTo: 'arrowclosed'`(to 端自動實心箭頭,方向可見;宿主可於表單改).
- reason 優先序:`no-endpoint` → `unknown-handle`(方位非四值)→ `self`(同節點任一把手,含出發把手自身)→ `not-connectable` → 圖層級(`missing-node` → `duplicate` → `custom`);取消路徑 `cancelled`.
- 游標/視覺(建線期間):畫布內一律 default;origin 與 valid → crosshair;invalid → not-allowed + danger ring;**出發節點之其他三把手**(節點 `data-connect-origin-node`)→ 淡化 + not-allowed(不需 hover 判定即刻正確);他節點任一把手 hover → 即時 valid/invalid.
- 預覽線:自出發把手(from 端,方位=出發邊)畫向游標(to 端);游標懸於把手時 to 端方位取該把手之邊,否則取出發邊之對邊(`anchorPolicy.oppositeSide`).
- `not-connectable` 把手 `pointer-events:none`,真實滑鼠 hit 不到(設計限制:不可連即無 affordance);該 reason 僅程式化路徑可達.

### 4.0 建線輸入空間(出發把手 × 落點)

| 落點 | 結果 | reason | 視覺 |
|---|---|---|---|
| 無把手(畫布/節點本體/邊) | 不建 | no-endpoint | 預覽線 default 色,游標 default |
| 把手之 `data-handle-position` 非四值(僅程式化/損壞 DOM 可達) | 不建 | unknown-handle | — |
| 出發把手自身 | 不建 | self | origin ring + crosshair(標示線之來源,不淡化) |
| 同節點其他三把手 | 不建 | self | 淡化 + not-allowed(即刻,不需 hover 判定) |
| 他節點把手,節點 connectable=false 或 nodesConnectable=false | 不建 | not-connectable(把手 pointer-events none,僅程式化可達) | — |
| 他節點把手,該節點已不在 nodes(DOM 殘影) | 不建 | missing-node | invalid |
| 他節點把手,已有同向 from→to(任何方位) | 不建 | duplicate | invalid ring + not-allowed |
| 他節點把手,validator 拒 | 不建 | custom | invalid |
| 他節點把手,合法 | 建 `{from,to,fromPosition,toPosition}` | null | valid ring + crosshair,線轉主題藍實線 |
| 他 flow 實例之把手 | 不建 | no-endpoint(describe 回 null) | 無標記 |
| 已存在 B→A 時自 A 拉到 B | 建(方向圖) | null | valid |

### 4.1 連接點幾何之單一來源
- 每節點四邊各一連接點,位置 = 形狀「該邊」之中點,由 `geometry.sideAnchorFraction(shape, side)` 給出外接矩形比例座標;把手渲染(`nodeStyle.handlePlacementStyle`)與邊端點(`geometry.getHandlePosition`)同用此 fraction(跨層測試 `unit-port-geometry` Q2 鎖定 7 形狀 × 4 邊 = 28 格).

| 形狀 | top | right | bottom | left |
|---|---|---|---|---|
| rectangle / diamond / ellipse | (0.5,0) | (1,0.5) | (0.5,1) | (0,0.5) |
| triangle-up / triangle-down | (0.5,0) | (0.75,0.5) 斜邊中點 | (0.5,1) | (0.25,0.5) 斜邊中點 |
| triangle-right / triangle-left | (0.5,0.25) 斜邊中點 | (1,0.5) | (0.5,0.75) 斜邊中點 | (0,0.5) |

- 射出方向恆為外接矩形該邊之外向法向量(由 side 決定,與點位無關);**有轉折點時亦然**:bezier 首/末控制點沿法線,step/smoothstep 兩端先沿法線走 `defOffset` 長之 stub 再轉向;建線預覽(游標端無節點矩形)之 step 路徑亦以 stub 保證方向.
- 形狀單一來源 `nodeStyle.nodeShape(node, defNode)`:`node.shape → opt.defNodeShape → 'rectangle'`,節點面/外框判定/把手佈局/邊端點皆經此解析.
- 把手圓心落在節點外框盒上(矩形之外框寬向外推;SVG 形狀外框為 0);hover 放大 2px 圓心不動.
- 節點無 `type`、無方位欄位;設定更新入口(`node-settings-update`)只受理 `NODE_SETTING_KEYS`,已移除欄位與未知鍵拒絕(不寫回、不發事件、console.warn);宿主資料若帶此類欄位一律不讀取.

### 4.2 邊方位之單一來源
- `fromPosition`:`conn.fromPosition → opt.defConnFromPosition → 'bottom'`;`toPosition`:`conn.toPosition → opt.defConnToPosition → 'top'`(`anchorPolicy.connSourceSide/connTargetSide`;非四值視為未給).
- 來源:拖曳建線寫入出發邊/落點邊;連線表單 From/To Anchor 寫入;宿主未給取 defConn.節點形狀/尺寸變更不改方位(fraction 隨外接矩形換算).

### 4.3 箭頭(marker)之單一來源
- `edgeMarker.resolveMarker(conn, defConn, 'start'|'end')`:type `conn.markerX → defConn.markerX → ''`(conn 明確 `''` 即無,不落回);size `→ 10`,夾 [4,40](**圖面 px**:`markerUnits=userSpaceOnUse`,隨 viewport zoom 同比縮放,與節點/線一致;不隨線寬);**填色與框色分列**(與節點之 `faceColor` / `edgeColor` 同一語彙):
  - fill:`arrowclosed` 取 `markerXFaceColor → defConn → 線色加深 20%`(`edgeMarker.darkenColor`;三角形填色,預設比線深使方向易辨,宿主改線色即跟隨),`arrow` 為 none(Face Color 不生效).
  - stroke:`markerXEdgeColor → defConn → 線色`.未給即跟隨線色**即為既有行為**,故本欄為向後相容之 opt-in 擴充;`arrow` 與 `arrowclosed` 皆適用——線式箭頭只有描邊,框色對它才是唯一有效的顏色.
  - 外框寬 = 線寬(0 合法).預設線色 `#b1b1b1`(中性灰).

  表單:欄位標籤 From/To Marker、Marker Size、Marker Face Color、Marker Edge Color(對應 `markerFrom`/`markerTo` 及其 `Size`/`FaceColor`/`EdgeColor`).三欄恆顯示(讓使用者知道可改)但依樣式決定可否改:**Size 有箭頭即可改;Face Color 僅實心可改**(線式 fill 恆 none,可改卻無畫面效果即半吊子 affordance);**Edge Color 線式與實心皆可改**;其餘 disabled(淡化 + 不可點).刪除鈕與色票確認鈕文字由 `opt.nodesSettingsDeleteText` / `opt.connsSettingsDeleteText` / `opt.settingsColorConfirmText` 設定(刪除鈕預設 `Delete`,色票確認鈕預設 `Confirm`).
- id 由規格單射編碼(各欄非英數字元 → `_hex`,欄間 `-`),`EdgeMarkerDefs`(defs,去重)與 `EdgeWrapper`(url)同一函式.
- viewBox `0 0 12 12`,三角形佔 1..11(四周留 1 單位供外框描邊,不被 marker overflow 裁切;外框寬換算上限 2 單位);尖端 (11,6) 對齊路徑端點;`orient="auto-start-reverse"` 使 from 端反向(此處之 `start` 為 SVG 屬性值,非資料鍵).size 即 marker viewport(含留白)之圖面 px.
- **端點語彙之分界**:資料鍵與公開 API 一律 `from`/`to`(`markerFrom*` / `markerTo*`,與 `conn.from`/`to`、`fromPosition`/`toPosition` 同一套);`resolveMarker(conn, defConn, 'from'|'to')` 亦然.僅 **SVG 屬性名** `marker-start` / `marker-end` 與 `auto-start-reverse` 保留 start/end——那是 SVG 規範所定,不可改;其對應在 `EdgeWrapper`(`markerFromUrl` → `:marker-start`)一處完成.
- 連線設定更新入口只受理 `CONN_SETTING_KEYS`(含 fromPosition/toPosition/marker*),未知鍵拒絕.

| type | 繪製 | fill(Face Color) | stroke(Edge Color) | 表單可改 |
|---|---|---|---|---|
| `''` | 無 marker | — | — | Face ✗ / Edge ✗ |
| `arrow` | `M1 1 L11 6 L1 11`(viewBox 12) | none(Face 不生效) | `markerXEdgeColor` → 線色 | Face ✗ / Edge ✓ |
| `arrowclosed` | `M1 1 L11 6 L1 11 z` | `markerXFaceColor` → 線色加深 20% | `markerXEdgeColor` → 線色 | Face ✓ / Edge ✓ |

### 4.4 刪除(單一 coordinator)
- 入口:節點表單、連線表單、刪除鍵、公開 API 全部走 `runDelete`;對宿主之完成事件只有 `elements-deleted`,序列一律 `update:nodes → update:conns → elements-deleted`(僅實際變動之集合).
- 確認閘門 await 後以「已確認集合(節點 + 連帶邊)」重解析:全數消失 → `not-found`;目標節點消失但已確認之連帶邊仍在 → 仍刪該邊(不留孤兒邊);期間出現未經確認之新相鄰邊 → `stale` 不刪.

## 5. 手勢生命週期(所有手勢一致)

| 階段 | 規則 |
|---|---|
| 啟動 | `activeGesture===null` 才可;啟動即 `closeAllPopups()`;根 class `vue-flow--gesturing`;手勢擁有者元素標 `data-gesture-owner` |
| 進行 | 非擁有者元素之 hover affordance(節點陰影/齒輪/四角、邊加深/齒輪/轉折點)抑制;非建線手勢中把手游標 default(不承諾可出發);`canOpenPopup()` 為 false(含公開 API `openNodeInfoPopup` / `openConnInfoPopup`——此二 API 回傳 wrapper 之裁決,拒開回 false——與 `panToNode({openPopup})` 之延遲開啟) |
| 終止 | mouseup / blur / buttons 復原 / destroy / 上鎖切換 → 同一收尾:清 activeGesture、根 class、owner 標記、各手勢暫態;connect 額外清 `data-connect-*`.**destroy 不發 `connect-end`**(元件已在銷毀流程,宿主無可收尾之 UI;其他取消路徑皆發 `cancelled`).實作單一來源:WFlowVue 持有之手勢(pan/drag/boxselect/connect)經 `endActiveGesture(reason)` 分派;子元件持有之 document 手勢(drag 追蹤/resize/waypoint/label)一律以 `js/domGesture.startDocumentGesture` 建立(mouseup/blur/buttons-lost 同一 disposer),destroy 與上鎖(`locked` prop watcher)呼叫 `cancelLocalGestures()`.驗收:`unit-gesture-lifecycle` G10 六手勢 × 五終止原因矩陣 |
| 上鎖切換 | 進入 locked 時:connect / boxselect / pan 取消;drag / resize / waypoint **取消提交**(ghost 復原,不寫回,不發 update).能力旗標與 locked 之組合單一表 `WFlowVue.can(action)`(drag/connect/resize/delete-key/multiselect) |

## 6. overlay 規則

- **popup-open**:同 flow 至多一個(WPopup 之 window mousedown 互斥 + 本系統對 `.stop` 路徑之 `closeAllPopups` 補強);任何手勢啟動關閉全部;popup 內 wheel/鍵盤屬 WPopup 範疇(Teleport).鍵盤 Delete 於 input/textarea/select/contenteditable/**button** 上不觸發畫布刪除.
- **multiselect**:隱藏全部 affordance;拒開任何 popup;節點 click=toggle;邊 click 不變更選取只發事件;dblclick/contextmenu **仍發**(資訊事件,刻意允許);hover 陰影/邊加深**仍在**(被動視覺,刻意允許);不得啟動 resize/connect/waypoint;建線進行中按住複選鍵建線續行.

## 7. 能力旗標(靜態,只擋啟動,不擋資訊事件與被動視覺)

## 8. 已知不修 / 設計限制

- popup 內滾輪不縮放 flow(Teleport overlay,WPopup 範疇).
- `not-connectable` 把手無 hover 回饋(pointer-events none,見 §4).
- 同頁多實例按住複選鍵同時進入模式(全域行為,刻意).
- 多條邊共用同一連接點不錯開(draw.io 同);需分離者改 From/To Anchor 或加轉折點.
- 重複判定不看方位(§1).
- 箭頭尖端與把手圓心重合;size 為 marker viewport(含 1/12 留白)之圖面 px.
- 建線中 hover 判定以「游標下把手 identity」為快取鍵:停在同一把手不動而宿主抽換 nodes/conns/validator 依據時,標記不重算(mouseup 之 commit 仍重新判定,不會建出不合法邊);屬合約外(手勢中抽換資料).
- 建線中之程式化 resize/形狀變更不重算起點(一次一手勢使 UI 路徑不可達;僅程式化可達).
- 重複判定不看方位(§1;Sol 建議可注入 uniqueness policy,業主裁定同向同節點對即重複).
- 缺省方位取 `defConn`(§4.2;Sol 建議依相對幾何自動選邊,裁定為確定性預設,不引入隨位置變動之自動機制).
- 節點尺寸只於 mounted/updated 量測並於初始化時由 WFlowVue 主動拉取一次(`pullNodeDimensions`);字型載入完成、純 CSS 版面變化等非 Vue 更新之尺寸變化不觀察(ResizeObserver 未導入:合約外,無觀察案例;宿主可呼叫 `fitView()`).
- step 路由不設快取(2026-08-28 移除模組級快取:跨實例共用且鍵不含障礙物;實測 80 節點/90 邊每幀 0.24ms,無需快取).
- `init` 於 fitViewOnInit=true 且節點為空時立即發出(空畫布可互動);之後首次填入節點再 fit 一次(僅當使用者尚未改動 viewport).
- fit 只以**節點包絡**計算(`nodesBounds`),連線不納入(同 React Flow `getNodesBounds`);極端轉折點可出窗,合約外.
- `zoomMin`/`zoomMax`/`panToNode` 之 zoom 參數不做值域防禦驗證(NaN/負值屬呼叫端錯誤;未觀察、無正常使用後果,§8 三條件不成立——2026-08-29 Sol 複審項,裁定不修).
- **設定表單不用原生 `<select>` / `<input type="text">`**,改用 `ui/SettingsSelect.vue` 與 `ui/SettingsText.vue`(封裝 w-component-vue 之 `WTextSelect` / `WText`).
  原生 `<select>` 之下拉清單開在 **OS 層**,由此生出兩個問題,換掉後皆消失:
  ①**曾造成實際缺陷**——OS 下拉的開合會使 `WPopup` 的 window 監聽器收到配不成對的 mousedown/mouseup(該元件以 mousedown 當下的座標決定 `clickContentInner`,再於 mouseup 沿用該旗標判斷關閉,`buildPopper.mjs:102-154`),被誤判為 outside 而關掉整個設定 popup(業主回報:切換 From/To Marker 即 popup 消失;當時以 `@mousedown.stop @mouseup.stop` 修正並經實機驗證).
  ②**自動化測不到**——Playwright/CDP 之點擊不會開啟 OS 下拉(headless 與 headed 皆實測,點第二下的 target 是底下的 DOM 元素而非選項),故當時只能以鍵盤路徑迂迴覆蓋.
  改用 DOM 下拉後:清單為一般元素,e2e 得以**真實點擊選項**(`selectByClick`);樣式亦完全可控(深色主題不再冒出系統色清單,§10.6 第 3 條).其下拉本身亦為 `WPopup`(巢狀於設定 popup 之內),已實測點選項不會關閉外層 popup 且值正確寫回.
  兩個封裝之存在理由:表單有 7 個下拉 + 4 個文字欄,外觀 props 若逐處手寫即同一規則手寫 11 次;且 `WTextSelect` 以「項目物件」為 value,與表單持有「值」的模型不同,轉換須集中一處.選項值域一律自既有單一來源衍生(`nodeStyle.SHAPES` / `anchorPolicy.SIDES` / `edgeMarker.MARKER_TYPES` / `edgePath.EDGE_TYPES`),不在表單另抄一份.
  尺寸對齊之陷阱:`WText` 的 `height` 指**內容區**高度,外框尚須加 padding 與 border(給 14 才得到與原生 number input 相同的 18px 外框;給 18 會得到 22).
- `WPopup` 之關閉契約即為「滑鼠 outside」(window `mousedown`/`mouseup`),不提供程式化或鍵盤關閉,亦非其設計目標.故「以滑鼠開啟色票面板後,改以鍵盤收合其所屬群組」這條混合路徑下面板不會關閉——該路徑係複審時刻意構造,非實際使用場景(真實滑鼠操作點標題列即判為 outside 而正常關閉),不成立為缺陷,不要求套件變更.同理 `WTooltip` 之 trigger 以滑鼠驅動,其 `tabindex` 不承諾鍵盤開啟.

## 9. 初始視口(fit-on-init)

- `opt.fitViewOnInit`(預設 true):首幀以 `vue-flow--pending` 隱藏渲染(viewport/background/panel `visibility:hidden`、根 `pointer-events:none`、`aria-busy`)→ `mounted` 後下一 tick 主動拉取全部節點實測尺寸 → `viewport.computeFitView`(padding 見下條;上限 `zoomMax`;容器 rect 逐軸 0 時回退 opt 寬高)→ 寫入 viewport → 解除隱藏 → 再下一 tick 發 `init`.使用者不會看到 fit 前之原點視口幀(E2E-038 以 rAF 逐幀驗證).
- **fit 之 padding 為 CSS 像素,非畫布座標**(2026-08-29 起之版本化行為變更).`opt.fitViewPadding`(預設 50,0 合法)之單位為容器像素:`zoom = min((容器寬 − 左 − 右) / 包絡寬, (容器高 − 上 − 下) / 包絡高, zoomMax)`,包絡中心對齊「容器扣 padding 後之可視區」中心.先前 padding 加在包絡上(畫布座標),螢幕實際邊距為 `padding × zoom`,圖越大留白越少(實測 zoom 0.148 時 50 只剩 7px).對標三家皆為螢幕層:Leaflet `fitBounds` padding、OpenLayers `View.fit` `padding:[top,right,bottom,left]`、React Flow v12.5 之 `'25px'`/`'10%'`/`{top,right,bottom,left,x,y}`.
- **padding 解析分三層**(單一來源 `viewport.resolvePadding`,逐邊回退 fallback 之同一邊):①opt 層——數值或 `{top,right,bottom,left}` 物件,缺漏/非法之邊回退 50;②`fitView(arg)` 層——物件為**對 opt 解析值之逐邊 patch**(如 opt 為 0 時 `fitView({left:120})` = `{120,0,0,0}`),非法參數回退整組 opt 值;③低階 `computeFitView`——未給 padding 即 0.
- **「0 = 貼邊」之精確語義**:0 表零人為留白;未受 `zoomMax` 夾限時,受限軸之螢幕邊距恰為該邊 padding(非受限軸置中而自然留有更多空間;小圖被 `zoomMax` 夾住時仍居中留白,屬 zoomMax 行為).
- **fit 不為工具區選單讓位**(同三家:Leaflet 連自家 zoom control 也不讓,官方文件明載 padding「usually left for controls」——留位是呼叫端以 padding 表達的事).預設不遮之保證:預設 padding 50 > 預設選單右緣 40px(面板距邊 10 + 鈕寬 30,由 Controls.menuDef 鎖定之預設維持),間隙 10px;`fitViewPadding: 0` 時節點可進入選單底下——使用者之明確選擇;放大選單(menuIconSize 等)者自行以物件 padding 讓位(如 `{left: 60}`).
- **不可行 padding**:單軸兩側和超過「軸長−1」時等比縮至「軸長−1」(保底 1px 可視區且必落於容器內,內容不會被推出畫面);僅真不可行時介入.
- 其他 overlay 不納入 fit:節點/連線 popup 為暫態(隨互動出現)、宿主自行疊加之外部 overlay 在元件合約外(皆以 `fitViewPadding` 物件形式自行讓位).
- `fitViewPadding` 僅作用於 fit(初始 fit 與 `fitView()`);`panToNode`/`zoomAtCenter`/resize 補正皆以完整容器為基準,不套 padding(fit-local 契約);修改 padding 不會即時重排,須再次 fit.
- `fitView` 與 `zoomAtCenter` 執行前取消進行中之 panToNode 動畫(與 resize 補正一致,避免動畫下一幀覆寫剛寫入之視口).
- `init` 語義 = 初始 viewport 已定案且可互動(此為 2026-08-28 起之版本化行為變更;先前於 opt 解析完即發).
- `fitViewOnInit=true` 時 `opt.center` / `opt.zoom` 不參與初始視口;false 時沿用二者且 `init` 同樣於首幀後發.
- 節點為空時 pending 立即解除;首次由空變非空且 viewport 未被改動(任何 `viewport-change` 即視為已改動)→ 再 fit 一次(仍屬初始化);之後不再自動 fit.
- 對標:React Flow `fitView` prop(nodesInitialized 後 fit,量測前節點 hidden)、Vue Flow `fit-view-on-init`;本系統同「先量測、再 fit、再顯示」,差異在以主動拉取取代回報計數(無計時器).
- **圖台尺寸變更(`opt.width`/`opt.height`)**:視口補正使舊圖台中心之內容於新圖台仍居中(zoom 不變),並發 `resize` 事件(payload `{width,height,oldWidth,oldHeight,viewport}`).對標:Leaflet `invalidateSize` 預設 `pan:true` 保中心且發 `resize(oldSize,newSize)`;OpenLayers view center 為模型狀態天然保中心;React Flow 無內建(官方建議 ResizeObserver + 自行 setViewport).補正屬程式化寫入:取消進行中之 panToNode 動畫、不套 panLimits(與其他程式化視口寫入一致)、不視為使用者改動 viewport(不影響空圖首次填入節點之初始 fit);初始化 pending 中不補正(初始 fit 逕以新尺寸計算).實際 DOM 尺寸非經 opt 之變化(CSS 縮放等)不觀察(合約外,同 ResizeObserver 之已知不做).

## 11. 設定表單之屬性分群(節點 / 連線 popup)

**分群定義單一來源**:`js/settingsGroups.mjs` 之 `NODE_SETTING_GROUPS` / `CONN_SETTING_GROUPS`,每群 `{ key, title, fields }`,陣列順序即呈現順序.表單 template 之群順序與此表一致(以 `v-for` 綁定,標題不另手寫).

| 元素 | 群(順序即由上而下) |
|---|---|
| 節點 | `basic` Basic(name, description)/ `appearance` Appearance(shape, faceColor, edgeColor, edgeWidth)/ `text` Text(fontSize, fontColor)/ `advanced` Advanced(popupDirection) |
| 連線 | `basic` Basic(name, description)/ `path` Path(type, fromPosition, toPosition, points)/ `appearance` Appearance(edgeColor, edgeWidth, animated)/ `arrows` Arrows(markerFrom / markerTo 各 type・size・faceColor・edgeColor,共 8 欄)/ `text` Text(fontSize, fontColor) |

- **群大小之判準**:依欄位語義關聯與使用頻率分群(progressive disclosure),**不以固定欄位數為門檻**——Miller 7±2 講的是即時記憶容量,不是可見表單的欄位上限,不作為切群依據.
- **對稱性**:兩表單共用之群鍵(`basic`/`appearance`/`text`)標題必須相同——同一件事在兩個 popup 用同一語彙;成員依元素型別而異.
- **群不與其唯一欄位同名**:單欄位群若標題與該欄位標籤重複(如曾經的 Shape / Shape)即併入語義相近之群.
- **狀態指示**:三角形朝右 = 收合、朝下 = 展開(`rotate(90deg)`,0.15s,與元素 affordance 之淡入淡出同時長).**整條標題列**(三角形 + 標題文字 + 列內空白)皆為可點區,非只有三角形.三角形色階走 `--vf-settings-caret`(淺色主題預設 `#666`).**對比須以「相鄰色」計算**:三角形坐在標題底色上而非 popup 底色上,`#666` 對淺色主題之標題底色為 5.04:1;先前用 `#888` 只有 3.11:1(雖仍過 WCAG 2.2 §1.4.11 之 3:1 但餘裕過小),而當時記載的 3.55:1 是誤以白底計算之高估值.**此契約須以語意斷言鎖定**——一階色差落在 pixel baseline 的 pixelmatch threshold 內,補強層抓不到.
- **群標題與欄位之視覺分區**:標題列有底色(`--vf-settings-surface`)、`padding:6px 12px`、`min-height:27px`,hover 加深至 `--vf-settings-surface-hover`;欄位列高 18px,故標題列有 9px 落差.高度為**契約**(明寫 `min-height`)而非內容偶然撐出.
  **只靠字重與字級(11px/600 對 12px/400、同色)分不出分區**,標題列高度亦不可與欄位列相當——此為已發生兩次之設計缺陷,不得回退.
- **標題列 full-bleed**:標題底色**貼齊 popup 左右邊緣**(inset 0),不留白邊、不留圓角.作法為以負 margin 突破表單水平內距(`--vf-settings-inline-padding`,12px)再以同值 padding 補回,故標題文字與欄位標籤落在同一條垂直線上(實測 x 相同).
  底色若左右各留白邊,會讀成「浮在中間的色塊」而非分區帶——此亦為已發生之設計缺陷.為此設定 popup 之 `paddingStyle` 歸零(`{v:0,h:0}`),內距全由 `ui/settingsForm.css` 掌管;資訊 popup 不受影響(仍 `{v:8,h:12}`).
  **此為本案在業主明確要求下的選擇,非業界通則**:Ant Design Collapse 為有外框圓角之 bounded 型並另提供透明 ghost 型,Carbon accordion 之靜止 header 為透明、僅以 subtle border 分區、hover 才上底色.不得由「full-bleed」再擴張推導出其他未經確認的決策.
- **相鄰收合群緊貼**:表單 `gap:0`,群與群之間僅以 1px `--vf-settings-divider`(取 popup 底色)區隔;留白隙會使一排標題帶讀成「分離的按鈕」而非分區清單.
- **分隔語彙一致**(水平):表單內**群層級**之邊界一律 full-bleed——群標題底色與**刪除區之上緣分隔線**同樣貼齊 popup 左右邊緣(inset 0);一條左右內縮的線配上貼齊邊緣的標題帶即為兩套規則.刪除鈕右緣以同值 padding 推回,與輸入控制項右緣落在同一條線.
  **子區塊層級**(轉折點之上緣線)則刻意**不** full-bleed:它在 Path 群內部,隨群內容縮排——層級不同,邊界語彙才不同.
- **縱向間距只有一個來源**(垂直):**所有邊界間距為 0**——群與群之間、末群與刪除區分隔線之間皆緊貼.縱向間距只屬於「展開內容自身的下緣」(群內容區之 `padding-bottom:10px`),收合時隨之歸零.
  故不得於刪除區另加 `margin-top`:那會出現「群與群貼齊、刪除線卻浮開一段」的兩套規則(且 flex item 之 margin 不與前一項 padding 折疊,兩者都給會疊成 20px).
- **主題適應**:群標題之底色/hover/分隔線/三角形一律走 CSS 變數,**不硬寫 hex**,且文字色 `inherit`(承 `opt.settingsPopupTextColor`).表單依 `opt.settingsPopupBackgroundColor` 之相對亮度自動切換:淺色底以疊黑加深(`rgba(0,0,0,0.06)` / hover `0.14`),深色底改疊白加亮(`rgba(255,255,255,0.10)` / hover `0.20`)並改用淺色三角形——否則深色 popup 上的標題帶會比背景更暗、三角形直接看不見.宿主可再覆寫這些變數細調.
  這些變數是**群標題專屬的語義 token**;預設值雖與工具列 hover 底色相近,但兩者不共用語義,工具列改色不應連動群標題.
- **各群獨立顯隱**:開一群不會關掉別群;預設展開 `DEFAULT_OPEN_GROUPS`(`['basic']`),宿主可經表單之 `defaultOpenGroups` prop 指定.該 prop 語義為**初值**(建立時取用一次),非受控 prop:掛載後再改不生效,表單亦不送出展開態變更事件——popup 每次開啟都會重建表單(NodeWrapper / EdgeWrapper 之 `v-if`),展開態刻意不跨開關記憶;宿主若需記憶,以 `SettingsGroup` 自行組裝表單.
- **收合之實作契約**:`height:0 + overflow:hidden + visibility:hidden`(**非** `display:none`)——收合內容仍參與寬度計算,故 popup 寬度不隨展開/收合跳動;`visibility:hidden` 同時使收合內容不可被 Tab 聚焦.
- **刻意不做高度過場動畫**:popup 由 popper 定位,高度逐幀變動會使整個 popup 於動畫期間持續位移;狀態連續性改由三角形旋轉表達(此為設計限制,非未完成).
- **無障礙**(W3C ARIA APG accordion pattern):標題按鈕**包在 `role="heading"` 內並帶 `aria-level`**(由 `SettingsGroup` 之 `headingLevel` prop 指定,預設 3)——只有 button + `aria-expanded` 僅達 disclosure pattern,accordion 明文要求 heading 層級;按鈕帶 `aria-expanded` / `aria-controls`,內容區 `role="region"` + `aria-labelledby`.button 原生即可 Tab 聚焦、Enter/Space 觸發,不另掛鍵盤處理.刻意用 `role="heading"` 而非 `<h3>`,避免設定表單之標題進入宿主頁面的文件大綱;heading wrapper 不用 `display:contents`(部分瀏覽器會將其移出無障礙樹而使 role 失效).
- **元件 id 之唯一性**:`aria-controls` / `aria-labelledby` 之 id 由 Vue 之 `_uid` 衍生,**僅保證同一個 Vue runtime 內唯一**.同頁載入兩份各自打包 Vue 的應用時 id 可能重複(合約外,不處理).
- **`excludes` 之群層行為**:整群欄位皆被 `opt.nodesSettingsExcludes` / `connsSettingsExcludes` 排除時,該群整項不渲染(不留空群);只排除群內部分欄位則該群仍在.
- **刪除區不歸入任何群**:破壞性操作恆顯示於表單最底部(既有 `border-top` 分隔),節點與連線一致.
- **高度上限**:`opt.settingsPopupMaxHeight`(CSS 長度字串,預設 `'400px'`;表單元件之 `maxHeight` prop)——超出即**於表單內捲動**,而非讓 popup 無限長高.**空字串為「明確不設限」之合法值**,故該 opt 之 kind 為 `defined` 而非 `truthy`(`truthy` 會把 `''` 回退成預設值而使此契約失效).刻意不用 `scrollbar-gutter:stable`:它在不需捲動時也預留捲動條空間,於 240px 寬的 popup 內是明顯的無用留白;改以 `scrollbar-width:thin`.表單另設 `overflow-x:hidden`——`overflow-y:auto` 會使 `overflow-x` 之 `visible` 計算成 `auto`(CSS Overflow §3),長標題或 min-content 撐開時會冒出水平捲軸.刪除區隨內容捲動(它是表單最後一項,不做 sticky);標題列亦不 sticky(4~5 個標題全部 sticky 會堆疊佔高).
- **字級單一來源**:表單 root 設 `font-size:12px`,由 `opt.settingsPopupTextFontSize` 以 inline style 覆寫;label 與輸入控制項一律 `font-size:inherit`,次級文字(群標題、轉折點子區塊標題與序號、刪除鈕)一律 `var(--vf-settings-font-sm)` = `0.92em`(預設 12px 下 11.04px).**不得硬寫 px**——否則該 opt 只改到部分文字,比例失衡且列高契約不穩.
- **次要文字色兩級**:`--vf-settings-text-muted`(子區塊標題)與 `--vf-settings-text-faint`(序號、空狀態提示),深色主題由表單改注淺色;分隔線色為 `--vf-settings-rule`(疊加而非硬寫 `#eee`).
- **邊界情形**:①`excludes` 使預設展開群(`basic`)整群不可見時,自動改展開第一個可見群,不讓 popup 開啟即全部收合;②長標題不換行、以 ellipsis 截斷,以維持列高契約;③標題列之鍵盤焦點環明寫為內縮式(`outline-offset:-2px`),UA 預設畫在元素外緣者會被表單之捲動邊界裁掉.
- **版面數字**(現況;於 Windows / Chromium 量得,屬環境量測而非跨平台契約):表單 `padding:8px 12px`;群標題列 `padding:6px 12px`、`min-height:27px`(第二個起因 1px 分隔線為 28px);群內欄位左縮排 16px(三角 10 + 間隙 6,水平 12px 已由表單內距提供),使欄位標籤左緣對齊群標題文字左緣(實測兩者 x 相同);內容區上距標題列 6px、下距 10px(**所有群一致,含末群**);刪除區 `margin-top:0`,故縱向邊界間距實測皆為 0.表單寬度:節點 239.3px、連線 255.8px,收合/展開/捲動皆同寬(`clientWidth` 與右對齊控制項之右緣 inset 亦不變).連線 popup 預設高度由分群前的 528px 降至 254px,全展開則封頂於 400px.
- **樣式歸屬**:兩表單之共用版面(`.vue-flow__settings-form` / label / 輸入控制項 / `.vue-flow__field--disabled` / 刪除區)在 `components/ui/settingsForm.css`,由兩個表單**各自 import**,使被外部單獨引用時自帶完整版面;`ConnSettingsForm` 之 `<style>` 只留連線專屬之轉折點樣式.(先前這些規則在 `WFlowVue.vue` 的全域 `<style>`,外部只 import 表單元件時拿不到,且連線表單自帶一份重複的刪除區樣式而節點表單沒有——兩者不對稱.)全域(非 scoped)之理由是 `vue-flow__` 前綴 class 為對外公開之覆寫點,**與 Teleport 無關**(`data-v` 為編譯期屬性,元素被搬到 body 仍帶著).
- **對外引用**:`SettingsGroup.vue`(可顯隱群組)、`NodeSettingsForm.vue` / `ConnSettingsForm.vue`(整份表單)、`settingsGroups.mjs`(分群定義)皆可由外部自 `w-flow-vue/src/...` 直接 import 作進階開發;兩表單之 `inject` 皆有預設值,可獨立掛載於 WFlowVue 之外.引用方之建置須能處理 Vue 2 SFC(同本專案引用 `w-component-vue` 之方式);`dist/w-flow-vue.umd.js` 只含 `WFlowVue` 本身.
